title: "Using OpenCode with Mycoroute"
---

This guide shows how to point [OpenCode](https://opencode.ai) at a Mycoroute router. OpenCode is an open-source coding agent (similar in spirit to Claude Code) that speaks the **OpenAI dialect** natively, so the integration uses the router's [`/v1/chat/completions`](/api/chat-completions) endpoint and side-steps Anthropic-specific compatibility issues entirely.

> **Snapshot date — last verified 2026-06-09.**
> No time-bound caveats apply today; this integration works against the router as shipped. Items in [Known limitations](#known-limitations) are tagged *time-bound* when relevant.

## What you get

- A coding agent (chat + file edits + bash) against any model in your fleet, with **no version-pinning workarounds**.
- Auth, quotas, and audit logging inherited from the router.
- Pure OpenAI dialect end-to-end — your vLLM agents serve it natively, no schema translation.

## Prerequisites

- A reachable Mycoroute router with at least one `llm` agent registered.
- The agent's backend must serve `/v1/chat/completions` (vLLM does by default).
- A Mycoroute API key with access to the model(s) you plan to use.
- One of: Node.js (for `npm`), Homebrew, or a POSIX shell (for the install script). For Node.js version guidance, see [Common prerequisites — Node.js](/integrations/overview#common-prerequisites--nodejs).

> **Tool-calling note (vLLM-side).** Once you start asking OpenCode to *do* things (file edits, bash, custom tools), vLLM must be launched with tool-call parsing enabled or the calls are silently emitted as plain text:
> ```bash
> vllm serve <model> \
>   --enable-auto-tool-choice \
>   --tool-call-parser qwen3_xml      # or 'hermes' for Qwen2.5
> ```
> Chat-only sessions work without these flags, so you can defer this until you actually exercise tools.

## Step 1 — Install OpenCode

OpenCode lives at [github.com/anomalyco/opencode](https://github.com/anomalyco/opencode) (it was formerly under `sst/opencode`). An older fork at `opencode-ai/opencode` was archived in September 2025 — do not use it.

Pick one install method:

```bash
# Install script
curl -fsSL https://opencode.ai/install | bash

# npm
npm install -g opencode-ai@latest

# Homebrew
brew install anomalyco/tap/opencode
```

Then disable auto-update so the binary cannot silently swap on you between sessions:

```bash
echo 'export OPENCODE_DISABLE_AUTOUPDATE=1' >> ~/.bashrc
export OPENCODE_DISABLE_AUTOUPDATE=1
```

> **Avoid OpenCode v1.0.164** — [issue #5674](https://github.com/anomalyco/opencode/issues/5674) drops the custom-provider `baseURL`/`apiKey` on that release. Any newer version is fine.

## Step 2 — Write `opencode.json`

OpenCode reads its main configuration from `~/.config/opencode/opencode.json` (global) or `./opencode.json` (per-project). Use the per-project file if you want different defaults in different repos; otherwise the global file is simpler.

```json
{
  "$schema": "https://opencode.ai/config.json",
  "autoupdate": false,
  "share": "disabled",
  "model": "mycoroute/Qwen/Qwen3.6-27B",
  "small_model": "mycoroute/Qwen/Qwen3.6-27B",
  "disabled_providers": ["anthropic", "openai", "google"],
  "provider": {
    "mycoroute": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Mycoroute Router",
      "options": {
        "baseURL": "https://<router-host>/v1",
        "apiKey": "{env:mycoroute_API_KEY}"
      },
      "models": {
        "Qwen/Qwen3.6-27B": {
          "name": "Qwen 3.6 27B",
          "limit": { "context": 131072, "output": 8192 }
        },
        "Qwen/Qwen3.6-35B-A3B": {
          "name": "Qwen 3.6 35B-A3B",
          "limit": { "context": 131072, "output": 8192 }
        }
      }
    }
  }
}
```

### What each piece does (and the rules that trip people up)

- **`provider.<id>`** — the *id* (here `mycoroute`) is an arbitrary label you choose. It becomes the prefix in every `provider/model` reference.
- **`provider.<id>.npm`** — the AI SDK adapter package OpenCode loads. `@ai-sdk/openai-compatible` is the right one for the router's OpenAI-format endpoint; it sends `Authorization: Bearer <apiKey>` automatically.
- **`baseURL` must end at `/v1`** — not `/v1/chat/completions`. The SDK appends the rest.
- **`apiKey: "{env:mycoroute_API_KEY}"`** — the `{env:NAME}` syntax pulls from the environment at runtime so the secret never sits in the config file. Env-var names are **case-sensitive** on Linux/macOS; the export name must match exactly.
- **`models.<id>`** — the model id (the key, e.g. `"Qwen/Qwen3.6-27B"`) is forwarded **verbatim** to the router. It must match what an agent registers; run `curl /v1/models` against the router to see the authoritative list.
- **Top-level `model` / `small_model`** — both use the **`provider/model`** form (`mycoroute/Qwen/Qwen3.6-27B`). The prefix before the slash must equal the provider id above; mismatches cause "provider not found" at startup.
- **`small_model`** — OpenCode's equivalent of Claude Code's HAIKU alias: used for lightweight background calls like title generation. Point it at a model on **your** router; if you leave it on the default it will silently try to reach hosted providers.
- **`disabled_providers`** — explicitly disabling Anthropic / OpenAI / Google avoids accidental fallback to a hosted provider if the config is misread.

### Set the env var (case-sensitive)

```bash
export mycoroute_API_KEY="<your-mycoroute-api-key>"
```

Verify:

```bash
env | grep mycoroute_API_KEY   # exact case must match the config interpolation
```

## Step 3 — Verify

Sanity-check the router (bypassing OpenCode):

```bash
curl -s https://<router-host>/v1/chat/completions \
  -H "Authorization: Bearer $mycoroute_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"Qwen/Qwen3.6-27B","max_tokens":32,
       "messages":[{"role":"user","content":"say hi"}]}'
```

If that returns a chat completion, the router/agent/vLLM chain is good. Then OpenCode:

```bash
# Non-interactive smoke test
opencode run "say hi"

# Per-model
opencode run "say hi" -m mycoroute/Qwen/Qwen3.6-27B
opencode run "say hi" -m mycoroute/Qwen/Qwen3.6-35B-A3B

# Interactive TUI
opencode
# inside the TUI: type /models to confirm the provider and models are listed
```

## Discovering available models

The router publishes the live model list (aggregated across all registered agents) at `/v1/models`:

```bash
curl -s https://<router-host>/v1/models \
  -H "Authorization: Bearer $mycoroute_API_KEY"
```

Use whatever string appears there as the model id in `opencode.json` — case- and slash-sensitive.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Startup error: provider/model not found | The prefix in `model` (`<id>/...`) does not match the key under `provider` (`<id>`) | Make both strings identical; the id is whatever you chose, but it has to be the **same** in both places |
| OpenCode reaches out to `api.anthropic.com` for titles | `small_model` left on a hosted-provider default | Set `small_model` to a model served by your router (`<id>/<model>`) |
| `401` from router | Env var name mismatch (`{env:NAME}` is case-sensitive) or wrong header | `env \| grep <name>` to confirm; OpenCode sends `Authorization: Bearer <apiKey>` automatically — no other header should be needed |
| `model_not_found` from router | `model` id does not match what any agent registers | `curl /v1/models` and update the model key + the top-level `model`/`small_model` |
| Chat works but tool calls have no effect (writes don't happen, bash doesn't run) | vLLM launched without tool-call parsing | Restart the agent's vLLM with `--enable-auto-tool-choice --tool-call-parser qwen3_xml` (or `hermes` for Qwen2.5) |
| `baseURL`/`apiKey` ignored — calls hit a default endpoint or fail with no obvious error | OpenCode v1.0.164 specifically — [issue #5674](https://github.com/anomalyco/opencode/issues/5674) | Upgrade to a newer release |
| `Route /api/messages not found` after switching to the Anthropic format | OpenCode's anthropic-format custom-baseURL has [open issues](https://github.com/anomalyco/opencode/issues/5163) | Stay on the OpenAI-compatible path (this guide); it is the supported route today |

### Reading the right logs

- **Router**: `docker logs gpt-router 2>&1 | grep -iE "chat/completions|policy|no eligible"`
- **Agent (proxy)**: `docker logs mycoroute-agent-<model> 2>&1 | tail -40`
- **Backend (vLLM)**: `docker logs vllm-<model> 2>&1 | tail -40` — request validation errors live here, not in the agent or router logs.

## Known limitations

- **`max_tokens` ceiling** — vLLM enforces `max_tokens ≤ max_model_len − prompt_tokens`. Set `limit.output` in `opencode.json` conservatively (e.g. `8192`) unless you know your agent's context budget; OpenCode passes `limit.output` straight through as `max_tokens`.
- **Backend 4xx responses currently bench the agent** via the router's `prev_failures` gate (router behaviour, not OpenCode-specific). A malformed client can transiently take all agents serving a model offline. Durable fix is a router-side change to distinguish backend 4xx from agent failures.
- **No in-session backend switching** (OpenCode architecture). OpenCode resolves its provider/endpoint at startup from the loaded config; to use Mycoroute and a hosted provider side-by-side, run two separate sessions with two configs (or two `OPENCODE_CONFIG` env values).
- **OpenCode share feature** uploads sessions to `opencode.ai` when enabled. This guide sets `"share": "disabled"` explicitly — keep that for self-hosted workloads, especially with regulated data.
