---
title: "Performance Characteristics"
---

Latency, throughput, and timing specifications for Mycoroute components.

### Latency Targets

| Operation | Target | Measured |
|-----------|--------|----------|
| Routing decision | Sub-millisecond | ~0.5ms |
| BadgerDB in-memory read | < 5µs | ~2.3µs |
| BadgerDB disk read (cached) | < 5µs | ~2.3µs |
| JWT validation | < 10ns | ~7ns |
| Prometheus counter increment | < 10ns | ~7-8ns |

### Throughput Characteristics

| Metric | Value |
|--------|-------|
| BadgerDB batch writes | Optimized for high throughput |
| libp2p stream multiplexing | Multiple concurrent streams per agent |
| HTTP/2 multiplexing | Multiple requests per connection |

### Timing Intervals

| Event | Interval | Rationale |
|-------|----------|-----------|
| Health check | 5 seconds | Balance between responsiveness and overhead |
| Unhealthy threshold | 15 seconds (3 × heartbeat) | Allow for transient network issues |
| Remove threshold | 30 seconds (6 × heartbeat) | Graceful degradation |
| Hardware sample | 2 seconds | NVML driver overhead |
| Engine sample | 500ms | vLLM/SGLang metrics are fast-changing |
| Routing signal push | 500ms | Fresh metrics for routing decisions |
| Heartbeat | 5 seconds | Health keepalive |

### Memory Footprint

| Component | Estimate |
|-----------|----------|
| BadgerDB memDB | ~1KB per agent (metadata + punctual) |
| BadgerDB diskDB | ~500B per agent (history) |
| Prometheus metrics | ~100B per counter/gauge |
| libp2p connection | ~10KB per agent |

### Scaling Characteristics

| Metric | Scale |
|--------|-------|
| Agents per Router | Tested: 100+, Target: 1000+ |
| Requests per second | Depends on backend capacity |
| Policy evaluation | O(n) where n = agent count |
| Storage writes | O(1) per request (counter increment) |
