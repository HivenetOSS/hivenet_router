Hivenet Router can reject an oversized request or briefly park work when the configured occupancy budget is full. These checks run before the request enters the routing queue and before an inference backend receives it.

Admission control currently applies to the allowlisted LLM passthrough routes:

- `POST /v1/chat/completions`
- `POST /v1/messages`
- `POST /v1/messages/count_tokens`

The embeddings and reranking handlers do not run these policy admission checks.

## Configure a policy

Admission fields live at the top level of a global or per-model policy:

```yaml
models:
  - Qwen/Qwen3.6-27B-A3B

mode: reserved
max_input_tokens: 131072
images_max: 8
admit_budget_tokens: 262144
max_inflight: 16

routing_policy:
  match:
    engine: vllm
  strategy: least-loaded
```

All four numeric limits are optional. `0` or an omitted field disables that check. Negative values make policy validation fail.

| Field | Current behavior |
| --- | --- |
| `max_input_tokens` | Rejects a request when the router's estimated text prompt exceeds the limit |
| `images_max` | Rejects a request carrying more images than the limit |
| `admit_budget_tokens` | Limits the token-weighted sum of in-flight requests for the model |
| `max_inflight` | Limits the number of in-flight requests for the model |

<Note>
  The token estimator is approximate. It extracts message text and estimates roughly one token per four bytes. Image content is counted separately by `images_max` because the text estimate does not include an image's model-specific token cost.
</Note>

## Request caps

The router resolves the effective policy for the requested model and checks text and image limits independently.

If either limit is exceeded, the router returns HTTP `400` with `input_too_long`:

```json
{
  "error": {
    "code": "input_too_long",
    "message": "input is 140000 tokens, over the model limit of 131072",
    "source": "router"
  }
}
```

Reducing only `max_tokens` does not fix this response. Reduce the input text or number of images.

## Occupancy budget

For each model, the router maintains an in-process occupancy total and in-flight request count. A request's initial footprint is:

```text
estimated input tokens + declared maximum output tokens
```

The declared output is `max_completion_tokens`, falling back to `max_tokens`. If neither field is present, the request initially reserves only its input estimate and the reservation grows as streamed output is observed.

The effective token budget is:

```text
floor(HIVENET_ROUTER_ADMIT_FRACTION × admit_budget_tokens)
```

`HIVENET_ROUTER_ADMIT_FRACTION` defaults to `0.85` and accepts values greater than `0` and at most `1`. Invalid values leave the default unchanged.

When the request would exceed the token budget or `max_inflight`, it waits for up to `HIVENET_ROUTER_ADMIT_PARK_TIMEOUT`. The default is `250ms`; `0` rejects immediately. The value uses Go duration syntax such as `100ms`, `2s`, or `1m`.

If capacity does not become available, the router returns HTTP `429`, sets `Retry-After: 1`, and uses `concurrency_limit_exceeded`:

```json
{
  "error": {
    "code": "concurrency_limit_exceeded",
    "message": "server at capacity for this model, please retry",
    "source": "router"
  }
}
```

Retry this error with bounded exponential backoff and jitter.

## Reserved and serverless modes

`mode` accepts `reserved` and `serverless`; omitting it selects `reserved`. The shared request and occupancy limits above run in either mode.

The current source also accepts these serverless key fields:

```yaml
api:
  mode: api-key
  keys:
    - key_hash: "<sha256>"
      key_preview: "sk-hivenet-...abcd"
      metadata:
        name: "Shared tenant"
        owner: "tenant-a"
      max_occupancy_share: 0.25
      quota:
        input_tokens_per_minute: 262144
        output_tokens_per_minute: 32768
```

<Warning>
  In the audited source, `input_tokens_per_minute`, `output_tokens_per_minute`, and `max_occupancy_share` are parsed and validated but are not consulted by the request-admission path. Do not rely on them as enforced runtime limits in this version. Existing RPM and daily token quotas remain enforced as described in the auth reference.
</Warning>

For a static API-key configuration that can reach a serverless policy, startup fails when a nonzero `input_tokens_per_minute` is lower than that policy's `max_input_tokens`. `max_occupancy_share` must be `0` (unset) or greater than `0` and at most `1`.

The policy loader also accepts `shed_if` with `kv_cache_utilization` or `waiting_requests`, but the audited request path does not currently evaluate this top-level block. Use `exclude_if` inside routing steps for live metric gates that are enforced today.
