title: "Hardware-Aware Routing"
---

Route requests based on GPU capabilities, thermal state, and resource utilization.

## GPU Model Routing

### Route by GPU Tier

```yaml
routing_policy:
  match:
    gpu_model: "NVIDIA H100"
  strategy: "least-loaded"

fallback_chain:
  - name: "a100-tier"
    match:
      gpu_model: "NVIDIA A100"
    strategy: "least-loaded"

  - name: "a10-tier"
    match:
      gpu_model: "NVIDIA A10"
    strategy: "least-loaded"
```

`gpu_model` is set by the operator at agent registration (e.g. `--gpu-model "NVIDIA H100"`). It is the only hardware property supported in the `match` filter. Use it to select GPU tiers and let VRAM requirements be implied by the tier.

### GPU VRAM Tier Routing

VRAM capacity cannot be matched directly — filter by `gpu_model` instead, since each GPU model has a known VRAM capacity:

```yaml
# Route to agents with ≥40GB VRAM by targeting A100/H100 models
routing_policy:
  match:
    gpu_model: "NVIDIA A100"   # 40GB or 80GB variant
  strategy: "least-loaded"
```

## Thermal-Aware Routing

### Exclude Overheated GPUs

```yaml
routing_policy:
  match:
    engine: "vllm"
  exclude_if:
    gpu_temperature_c: { gt: 80 }
  strategy: "least-loaded"
```

### Graduated Thermal Limits

```yaml
routing_policy:
  match:
    region: "EU"
  exclude_if:
    gpu_temperature_c: { gt: 75 }  # Strict for primary

fallback_chain:
  - name: "relaxed-thermal"
    match: {}
    exclude_if:
      gpu_temperature_c: { gt: 82 }  # Relaxed for fallback
    strategy: "least-loaded"
```

## Multi-Constraint Routing

### Combined Hardware Filters

```yaml
routing_policy:
  match:
    gpu_model: "NVIDIA A100"
  exclude_if:
    gpu_temperature_c: { gt: 80 }
    gpu_vram_used_percent: { gt: 0.85 }
    kv_cache_utilization: { gt: 0.85 }
  strategy: "least-loaded"
```

## Use Cases

### Batch Inference (High VRAM)

Route batch jobs to high-VRAM GPUs using the `gpu_model` tier as a VRAM proxy:

```yaml
routing_policy:
  match:
    tags: ["batch"]
    gpu_model: "NVIDIA H100"   # H100 = 80GB VRAM
  exclude_if:
    gpu_vram_used_percent: { gt: 0.7 }
  strategy: "least-loaded"
```

### Real-Time Inference (Low Latency)

Route real-time to fastest GPUs. `srtt` is in **milliseconds**:

```yaml
routing_policy:
  match:
    tags: ["realtime"]
    gpu_model: "NVIDIA H100"
  exclude_if:
    srtt: { gt: 200 }          # Exclude agents with SRTT > 200ms
    gpu_temperature_c: { gt: 75 }
  strategy: "least-loaded"
```

> **Note:** A `lowest-srtt` strategy is planned but not yet implemented. Use `least-loaded` with an `srtt` gate in the meantime.

### Cost-Optimized Routing

Prefer cheaper GPUs when possible:

```yaml
routing_policy:
  match:
    gpu_model: "NVIDIA A10"  # Cheaper
  strategy: "least-loaded"

fallback_chain:
  - name: "a100-backup"
    match:
      gpu_model: "NVIDIA A100"
    strategy: "least-loaded"

  - name: "h100-last-resort"
    match:
      gpu_model: "NVIDIA H100"
    strategy: "least-loaded"
```

### Green Computing

Route to a specific region with renewable energy (power-based gating is not yet a supported `exclude_if` field — use `gpu_model` or `region` to target more efficient hardware):

```yaml
routing_policy:
  match:
    region: "EU"           # Renewable energy region
    gpu_model: "NVIDIA A10" # Lower TDP than A100/H100
  strategy: "least-loaded"
```

## Monitoring Hardware Utilization

### GPU Distribution

```promql
# Requests routed by engine type
sum by (engine) (rate(mycoroute_routing_requests_routed_total[1h]))
```

### Thermal Distribution

```promql
# Agents by temperature range
mycoroute_agent_gpu_temperature_celsius < 70  # Cool
mycoroute_agent_gpu_temperature_celsius >= 70 and mycoroute_agent_gpu_temperature_celsius < 80  # Warm
mycoroute_agent_gpu_temperature_celsius >= 80  # Hot
```

### Power Efficiency

```promql
# Requests per watt
sum(rate(mycoroute_routing_requests_routed_total[1h])) / sum(mycoroute_agent_gpu_power_watts)
```

## Capacity Planning

### VRAM Budgeting

```
Total VRAM = sum(gpu_vram_gb) across agents
Model VRAM = model_params × 2 bytes (FP16)
KV Cache per request = context_length × hidden_size × layers × 2 / 1024^3

Max concurrent = (total_vram - model_vram) / kv_cache_per_request
```

### Power Budgeting

```
Facility power limit: 10kW
GPU power: 400W per A100
Max GPUs = 10000W / 400W = 25 GPUs

With 80% efficiency: 20 GPUs recommended
```
